# 评测协议

## 三种不同问题

1. **原问题回查**：`make-eval` 生成 `self_retrieval` 文件。问题在索引的检索字段中出现过，只用于一致性检查。
2. **检索泛化**：人工整理改写、新问题、易混淆负例，标注正确证据文档；用 `curated` 文件。
3. **回答质量**：在同一固定问题集上比较实际证据、拒答、引用和答案。ROUGE 或有效引用编号都不能替代临床事实审核。

检索知识库应包含支持答案的资料，不必为了“留出”移除正确证据。需要隔离的是开发/测试问题、SFT 训练样本，以及同病例/近义改写组；避免使用测试问题或标签选择阈值。规范化问题分组仅消除明显重复，不处理全部语义近似。

## 人工评测文件

先从新索引 `chunks.json` 获取 `document_id`，再替换下面的示意 ID。原来的 `med_000...` 不能用于 v2。

```json
{
  "schema_version": 2,
  "kind": "curated",
  "items": [
    {
      "id": "case-001",
      "question": "经人工核对的新问法",
      "answerable": true,
      "relevant_document_ids": ["doc_REPLACE_WITH_REAL_ID"],
      "reference_answer": "可选的人工参考答案"
    },
    {
      "id": "case-002",
      "question": "知识库无法回答的问题",
      "answerable": false,
      "relevant_document_ids": []
    }
  ]
}
```

空问题、重复 ID、缺少标签、不存在的 gold ID 一律报错，不把坏样本默默算进分母。报告提供逐条结果以供审查。

## 指标口径

- Hit@k：前 k 个去重后的文档中是否有任一标注文档。
- Recall@k：前 k 个文档覆盖了多少个标注文档，不等同于 Hit@k。
- MRR：候选范围内第一个相关文档排名的倒数；最多考察 `candidates` 个原始块。
- 不可回答拒答率：不可回答样本中 `insufficient_evidence` 的比例；服务错误单独统计。
- 可回答作答率：可回答样本中 `answered` 的比例，**不是准确率**。
- ROUGE-1/2/L：显式按汉字/英文数字词分词，逐条输出；空输入得零。只衡量文本重合。
- p50/p95：实际 pipeline 请求的总耗时，包括第一次可能出现的模型冷加载；单独的检索指标采集会预先执行检索，因此该报告不是严格的全冷启动基准。吞吐测试应另行控制预热、并发和硬件。

推荐实验矩阵：lexical + 摘录、dense + 摘录、dense + reranker + 摘录、dense + reranker + 基座生成。只有先固定评测集、开发集阈值和模型版本，才能比较效果。当前仓库没有 v2 的真实模型成绩。

## 训练评测

`split` 写入固定 train/validation 文件。`train` 检查文件哈希及规范化问题交集，直接分别构建两个 Dataset。过长样本的 ID 会被记录，避免分母无声变化。EOS 被监督，PAD==EOS 时按长度构造 attention mask，不遮住真实 EOS。

旧模型的训练标签和旧留出集曾存在问题，不能将旧数字与重构后的结果混合成一次有效对照。训练函数本次可做纯逻辑及本地小模型验证；完整 CUDA/QLoRA、真实医疗模型、数据质量审核仍需独立实验。
